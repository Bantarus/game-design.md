# game-design.md v0.4: release notes

> **Draft.** v0.4 is not released. The version bump (0.3.0 → 0.4.0) awaits review. The evidence section is final (D-032); the rest is written for the bump and may still change with it.

## What v0.4 is

v0.3 shipped the format. v0.4 is about **reading and checking it**:

- **Reading:** a tree can be read without opening whole files. `gdmd view` and `gdmd graph` project a tree into the blocks and reference edges a task needs, and the agent card gives an agent the spec in 8.5 KB instead of 147 KB.
- **Checking:** lint now enforces what the spec already claimed. The normative JSON Schema, the content-entity rules and several MUSTs that v0.3 only stated are now lint rules.
- **Measuring:** the dogfood harness, headless agent sessions on copies of this repository, is the routine evidence surface (spec §11.3), and two pre-registered studies ran on it.

The format itself changes little; see "Format changes" below. A v0.3 tree that linted clean can now report findings, so read "Upgrading from v0.3" before you bump a tree.

## Evidence: what the dogfood studies measured

v0.4's evidence comes from the dogfood harness (spec §11.3, D-023). Headless coding-agent sessions (`claude-sonnet-5-5`) run fixed tasks on isolated copies of this repository, deterministic checkers grade them, and locked rules, committed before any data, turn the results into verdicts. n is small (3 repeats per cell) and there is one subject model, so every number below is descriptive of these runs.

### Projected views (`gdmd view` / `gdmd graph`)

The two studies are always cited together (D-032).

- **Study 1, Rule V: NULL** on this repository's own trees, which are small (tens of KB).
  - The v0.4 world with the views arm consumed a median 15.6% fewer consultation bytes than the v0.3 baseline, against a 30% threshold.
  - [`docs/case-studies/dogfood-01.md`](../case-studies/dogfood-01.md).
- **Study 2, Rule V2: PASS** on a content-heavy synthetic tree: generated, 320 content entities, with a planted reference graph.
  - Consultation was a median **33.3%** lower, against the same 30% threshold, with no loss of success.
  - **The graph-shaped tasks drove it:** the two impact tasks and the backward multi-hop lookup read 59–92% fewer bytes, each answered with one to three `gdmd graph` calls.
  - The forward lookup was flat (+7.4%).
  - The guarded maintenance and negative-control tasks consulted more under views (−53% and −126%), from one added overview or `--grep` call.
  - The PASS is narrow: the median of six tasks falls between +7.4% and +59.3%.
  - [`docs/case-studies/dogfood-02.md`](../case-studies/dogfood-02.md).
- **Not a session-cost claim.** The primary is consultation bytes: the tool-result bytes returned to the model. Occupancy and cost are secondaries, and they carry the two worlds' difference in spec size.
- The spec makes no empirical claim about views. §9.9 defers to §11.3.

### The agent card (`CLAUDE.md` imports `docs/spec-card.md`)

- **Rule C (study 1) and Rule C2 (study 2): PASS.** Importing the generated card instead of the full spec lowers median per-turn context occupancy by about **47k tokens** (D = 46,769 and 47,158), with no loss of success.
- **Non-inferiority was tested only at the ceiling.** Every run in both studies succeeded. So neither study shows the card is safe on tasks that need spec text beyond it, and no card run asked for it (`gdmd spec --section`: 0 calls).

### Observed (descriptive only)

- On study 2's large tree, subjects in **both** C2 cells used `gdmd view` / `gdmd graph` without the arm text mentioning them: 33 and 22 calls, in 12 of 18 runs each.
- In study 1's Rule C, on the small trees, no run did.

## New commands and options

| Command | What it does | Spec |
| --- | --- | --- |
| `gdmd view <tree>` | Projected views: an overview index, `--full`, `--grep`, `--ref <{ns.id}> [--hops N]`, `--flat`, `--role`, `--json`. Every line is verbatim source, and every elision carries a `<path>:<start>-<end>` pointer. | §9.9.3, D-027 |
| `gdmd graph <tree>` | The tree's reference graph: `--impact`, `--from/--to` (shortest paths), `--cycles`, as text, JSON or DOT. | §9.9.4, D-027 |
| `gdmd spec --card` / `--section <id>` | The agent card, generated from the spec's structure, and any one section verbatim. `CLAUDE.md` now imports the card. | §9.4, D-024, D-029 |
| `gdmd hook check --show-tokens` | The pre-commit report also prints the YAML a staged change may have made stale. | §9.7, D-028 |
| `gdmd verify --baseline <prior report>` | Reports `verify-result-regression` for each target that passed in the baseline and fails now. It was specified since v0.1.1 but never built. | §9.5.4, D-045 |

Views and graph are computed on every call, store nothing, and summarize nothing: every edge is a `{ns.id}` reference the author wrote.

## Lint now enforces what the spec claimed

v0.3's §11 conformance claim was weaker than its text: lint never ran the schema and never validated content entities ([v0.3 conformance correction](v0.3-conformance-correction.md)). In v0.4 every §11 conformance item has a lint rule behind it. How completely each rule covers its item is not claimed.

| Rule | Severity | Checks | Decision |
| --- | --- | --- | --- |
| `schema-violation` | error | Each file's frontmatter against its `file_type`'s branch of the §10 JSON Schema. | D-034 |
| `content-entity-invalid` | error | Each content entity against its content-schema's `schema:`, `id` against the file stem, and entities no `data_dir` covers. Also a `data_dir` whose folder is not named after the `entity:`, and a `data_source` that differs from `data_dir`. | D-035, D-037 |
| `trajectory-sort-by-missing` | error | Every array in a `trajectory.schema` declares a `sort_by:` key list (§9.5.5's MUST). | D-048 |
| `implementation-pointer-outside-repo` | warning | An implementation glob whose base leaves the git repository. | D-038 |

Also changed:

- A bare-string state-machine `event:` is now a `schema-violation` **error**. It was the `undefined-event` warning, now retired (D-046).
- **Whole-namespace references** in an invariant's `applies_to` (`"{resources}"`) are resolved. A `numeric_domain` invariant over one now checks every member, where before it checked nothing (D-033).
- `balance-target-untyped` is retired: `schema-violation` reports the same defect as an error (D-040).
- `prototyped-without-pointer` no longer fires on `balance_targets`, whose schema forbids `implemented_in` (D-036).

## Format changes

| Change | Effect on trees | Decision |
| --- | --- | --- |
| An invariant's `applies_to` accepts `{namespace}`, which names every token of the namespace. | The 8 trees that used it are now schema-valid. | D-033 |
| An entity's `data_source` is **deprecated**: optional, and removed before v1.0. When present, it must equal its content-schema's `data_dir`. | Every in-repo value already did. | D-037 |
| `schema_ref` is removed from `$defs.Entity`. | No tree used it. | D-039 |
| A transition `event:` must match `{events.<id>}` in the schema. | Every in-repo transition already did. | D-046 |
| The spec now says what the tools always did:<br>• paths are relative to the tree root, and `../` may leave the tree but not the repository (D-038);<br>• `{entities.<kind>.<id>}` resolves by directory name (D-037);<br>• the context-local prefixes are exactly `{actor, target}` (D-047);<br>• `pillars`, `player_experience_goals` and `verify_targets` / `adapters` are reserved keys, not referenceable namespaces (D-039). | None. | D-037, D-038, D-039, D-047 |

## How the spec states plans now

- **The spec states current behavior only (D-044).** Seventeen spec lines had promised behavior by version ("ratchets to error in v0.3"), and most of those dates had passed unapplied.
- **Planned changes are rows in the Ratchet Register** (`DECISIONS.md` OI-010), each written as **trigger → action**. A target version is optional and not binding.
- **Release procedure:** AGENTS.md requires the register to be reviewed before every version bump. For 0.4.0 the review found no trigger observed.

## Upgrading a tree from v0.3

1. **Set `spec_version: 0.4.0`** in the tree's files.
2. **Run `gdmd lint <tree>`.** A tree that was clean under v0.3 can now report:
   - `schema-violation`: frontmatter outside the §10 schema. In this repository's trees, two defects of this kind went unseen at v0.3: a verb's `time_cost` nested inside `cost:` (D-030), and a content-schema without `data_dir` / `count_target` (D-031). A bare-string transition `event:` also lands here now; write `"{events.<id>}"`.
   - `content-entity-invalid`: an entity that its content-schema rejects, an `id` that is not the file stem, a content directory that no `data_dir` covers, or a `data_dir` folder not named after its `entity:`. Its first run found a mangled key in this repository's deckbuilder schema (fixed in `1bcfc01`).
   - `trajectory-sort-by-missing`, if the tree declares a trajectory.
   - `implementation-pointer-outside-repo`, a warning, if a glob leaves the repository.
   - `invariant-violation` or `broken-ref` from `applies_to: ["{namespace}"]` items, which are now checked.
3. **`data_source`** can be deleted, or kept equal to the content-schema's `data_dir`.
4. **Trees created with `gdmd init --genre party-rpg` at v0.3** carry an incomplete heroes content-schema. See the [v0.3 conformance correction](v0.3-conformance-correction.md) for the two lines to add.
5. **Scripts that parse `gdmd hook check` output:** inside a git repository, `triggered by:` now names files relative to the repository root, as git stages them, not relative to the tree (D-038).

## Not in v0.4

- **Open ratchets** stay in the register (OI-010), each with its trigger. Examples: a closed `do[]` `kind:` vocabulary waits for a second engine-backed tree; raising `determinism-undetermined-rule` waits for a structured silence mechanism.
- **Two design notes,** with nothing built:
  - [`view-usability.md`](../design-notes/view-usability.md): view and graph usability candidates from the studies (OI-007). Any change to view output needs its own measurement before any claim.
  - [`session-decision-drift.md`](../design-notes/session-decision-drift.md): flagging token decisions made in agent sessions that never reached the tree (the kickoff's WS5).
- **§11.2's queued validation claims** (cost amortization, the longitudinal living-doc property) are still unvalidated. The dogfood studies measure consultation and occupancy within a session, not across a project's life.
